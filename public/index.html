HELP CENTER

Setup guide

Follow these steps to create a reliable backup without needing to be a developer.

QUICK START

Recommended order

  1. Add a databaseEnter the server address and login. Passwords may be blank when your database allows passwordless login.
  2. Test the databaseUse Test connection before saving. Fix this step before continuing.
  3. Add storageLocal disk is easiest. FTP/FTPS and Synology are usually simpler than cloud tokens.
  4. Test storageSave the target, then choose Test on its storage card.
  5. Create a scheduleSelect all databases or choose specific databases, set the time, and keep at least one backup during your first test run.
  6. Run it once manuallyUse Run now and confirm the file exists at the destination.
IMPORTANT

Before using cloud storage

Google Drive and OneDrive require OAuth credentials. Use an access token for quick setup, or provide a refresh token with the OAuth client ID and secret so unattended schedules can renew access automatically.

Use the least-privileged provider permission and keep the refresh token, client secret, and application encryption key private. VaultBack encrypts saved credentials and never returns them to the browser.

Never paste a token into chat, email, screenshots, or a public issue. The safe configuration export intentionally excludes all credentials.

FTP / FTPSUsually easiest

Ask your hosting provider or server administrator for the FTP hostname, port, username, password, and remote backup directory.

  1. Create a dedicated account that can access only the backup folder.
  2. Use FTPS when available. Port 21 is common for FTP/explicit FTPS, but use the port given by your provider.
  3. Enter the server details in Storage targets and choose Test after saving.
Example
Host: ftp.example.com · Port: 21 · Folder: /backups
Synology WebDAVNAS option

On the Synology NAS, open WebDAV Server, enable HTTPS, create a dedicated user, and give that user access to the backup shared folder.

  1. Use an address such as https://nas.example.com:5006/backups.
  2. Enter the NAS username and password in VaultBack.
  3. Use the NAS certificate hostname instead of its IP address when possible, then choose Test.
  4. If your private NAS uses a self-signed certificate, enable Allow self-signed certificate on that storage target only when VaultBack and the NAS are on a trusted private network.

Open Synology’s WebDAV guide ↗

Certificate verification stays enabled by default. For an internet-facing NAS, install the NAS CA certificate or use a publicly trusted certificate instead of allowing self-signed certificates.
Google DriveOAuth token

Google does not provide a normal “FTP password” for Drive. You must authorize an application and obtain an OAuth access token.

  1. Open Google’s OAuth documentation or OAuth Playground.
  2. Authorize Drive upload access for the Google account that owns the destination folder.
  3. Copy the access token into VaultBack and copy the folder ID from the Drive URL into Folder ID.
  4. Remember that access tokens expire; replace the token before a scheduled backup fails.

Google OAuth setup ↗ · Google OAuth Playground ↗

OneDriveOAuth token

OneDrive uses Microsoft Graph. A Microsoft Entra app registration and delegated access token are required.

  1. Ask your Microsoft 365 administrator to create or approve an app registration.
  2. Grant the least-privileged Files.ReadWrite delegated permission needed for the backup account.
  3. Sign in to the approved authorization flow, copy the access token, and paste it into VaultBack.
  4. Enter a path such as vaultback/backups/database.sql.gz and monitor token expiry.

WHEN SOMETHING FAILS

Simple checks

Connection refusedConfirm the host and port are reachable from the machine running VaultBack. Do not use 0.0.0.0 as a destination.
Permission deniedAsk the storage or database administrator to grant the dedicated account access to only the required folder or databases.
Cloud token rejectedGenerate a new token, confirm it has upload permission, replace the old value, and run a test backup.
